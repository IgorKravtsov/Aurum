# Rust workspace с общим ядром без IO и мобильными клиентами через UniFFI

Бэкенд (FastAPI) и CLI (Node) переписываются на Rust одним Cargo workspace без изменения REST-контракта, чтобы iOS и Android могли переиспользовать тот же код. Мобильные приложения — тонкие клиенты self-hosted сервера: общий код для них — `aurum-domain` (DTO контракта, валидация, чистые расчёты, без IO) и `aurum-client` (HTTP-клиент), экспортируемые в Swift/Kotlin через UniFFI из `aurum-ffi`. Граф зависимостей: `domain` ← `server`, `client`; `client` ← `cli`, `ffi`. Веб-фронтенд остаётся на React.

## Considered Options

- **Offline-first (SQLite на устройстве + синхронизация)** — отклонено сейчас как на порядок более дорогое и требующее отдельного дизайна конфликтов; ядро без IO оставляет этот путь открытым.
- **Переписать фронтенд на Leptos/Dioxus** — отклонено: меняет интерфейс, что противоречит требованию функциональной эквивалентности.
- **cbindgen/C ABI, flutter_rust_bridge, crux** — отклонены в пользу UniFFI: одна генерация для Swift и Kotlin, поддержка async и ошибок, нативный UI.

## Consequences

- DTO сервера и клиентов — одни и те же типы, поэтому контракт не может разойтись между сервером, CLI и мобильными приложениями.
- Хранение секретов (basic auth) — ответственность платформы (Keychain, Keystore, конфиг CLI), ядро ничего не пишет на диск.
